# 伏笔台账工作流（跨章全局 ledger）

> 定位：解决长篇小说「早期暗线忘兑现 / 重复埋 / 中段散」的病。根基文档管"写什么"、门禁管"单章对不对"，本文件管"全书伏笔一条不漏"。
> 设计阶段 `plot-threads.md`/`world-gradient.md`/`thread-weave.md` 的登记表是**蓝图**，伏笔台账是逐章**实况镜像**——蓝图↔实况卷末对齐，故事才会越连越紧、终成经典。

---

## 产出物

`伏笔台账_<书名>.md`，与根基文档同目录，每章读写，随写随长。

## 条目 Schema

| 字段 | 说明 |
|------|------|
| 编号 | F-001 递增 |
| 类型 | 暗线 / 设定钩子 / 物品 / 台词回调 / 能力伏笔 / 悬念 / 红鲱鱼 |
| 埋下 | 第X章 + 一句话锚点（具象画面 / 物件 / 台词） |
| 状态 | 待兑现 / 部分兑现 / 已兑现 / 已废弃 |
| 计划兑现 | 指回初级大纲某卷某章（卷级即可） |
| 关联 | 关联角色 / 暗线 / 梯度层 |
| 备注 | 交汇触发条件、反转设计、回收方式 |

## 铁律

- 每章成稿（七步循环「故事线更新」步）必须扫本章：**新埋 → 追加条目**；**被兑现 → 改状态**；发现**重复埋 → 合并或标红鲱鱼**。
- 每章开工前（Hook 2 翻文档）必须 `grep` 台账，列出「待兑现且已临近计划章」的条目，本章或近期必须安排推进 / 兑现，**禁止无限悬空**。
- 门禁 Hook 12 增「伏笔闭环检查」：本章应兑现的是否兑现、新埋的是否登记、有无新增未铺垫悬念（见 `gate-hook-checklist.md` 第 9 项）。
- 台账**只增不删**：已兑现改状态不删行；已废弃标「已废弃」留痕，便于后期回收（回收式清算爆点）。
- 红鲱鱼（假伏笔）也登记，类型标「红鲱鱼」，避免与真伏笔混淆；揭晓时改状态并标注反转。

## 调用协议

1. **开工**：`grep 伏笔台账` → 取「待兑现 + 临近」清单 → 纳入本章计划（Hook 10）。
2. **成稿**：扫新埋 / 新兑现 → 更新台账状态 → 存盘。
3. **门禁**：Hook 12 第 9 项对台账核对。
4. **卷末复盘**：蓝图（plot-threads / world-gradient / thread-weave 登记表）↔ 台账实况对齐一次；蓝图有伏笔漏进台账 → 补；台账有伏笔无蓝图支撑 → 回填设计或标红鲱鱼。

## 与根基文档咬合

- 伏笔台账是「暗线 / 梯度 / 多线」设计表的**运行期镜像**：设计定方向，台账记实况，二者咬合 → 故事从"一条线"织成"一张越收越紧的网"。
- 配合 `character-evolution.md` 的角色活档案：伏笔常挂在角色暗线 / 关系网上，台账推进即暗线推进，暗线推进即角色丰满。
